# KIET Smart Attendance and Performance Analyser

**Institution:** KIET Institutions  
**Target Group:** First-Year B.Tech Students across Emerging Branches  
**Project Level:** 2nd-Year B.Tech AI & Data Science Mini-Project  
**Footer Tagline:** Built with Python • Flask • HTML • CSS • JavaScript • SQLite  

---

## 1. Project Overview

The **KIET Smart Attendance and Performance Analyser** is an academic management and early-intervention web application designed specifically for **KIET Institutions**. It empowers department heads, faculty members, and first-year coordinators to seamlessly monitor subject-wise attendance and marks, identify students requiring timely academic support, and benchmark performance across engineering branches.

### Target Branches
The system provides multi-branch comparison and individualized student tracking for all five KIET first-year AI/Data/Computing specializations:
1. **AI** — Artificial Intelligence
2. **AIDS** — Artificial Intelligence and Data Science
3. **AIML** — Artificial Intelligence and Machine Learning
4. **DS** — Data Science
5. **CYBER** — Cyber Security

## 2. Key Features

### Role-Based Access Control (RBAC)
- **Admin / Teacher**:
  - Secure session-based login and logout.
  - Interactive **Academic Analytics Dashboard** with key institutional metrics.
  - **Student Management**: Add, view, edit, search (instant search by name or roll number), filter (by branch, semester, status), and delete student profiles.
  - **Attendance Management**: Step-by-step flow (`Branch → Semester → Subject → Student Entry`) with real-time percentage computation and color-coded eligibility bars.
  - **Marks Management**: Step-by-step entry for marks obtained vs. maximum marks with automatic percentage and grade band calculation.
  - **Branch Comparison**: Comprehensive comparative data table, automated analytical insights, and 6 dynamic Chart.js visualizations.
  - High-priority **Students Needing Attention** monitoring table with automated recommendations.
- **Student**:
  - Secure student login with credentials generated by faculty.
  - Dedicated, isolated **Student Dashboard** restricted strictly to their personal records.
  - Visual subject-wise attendance progress bar chart with 75% university eligibility line.
  - Visual subject-wise academic marks breakdown chart.
  - Personalized status badge and tailored academic improvement recommendation.
  - Strict security guards preventing access to administrative routes, modifications, or peer data.

### Automated Performance Analysis Rules Engine
Every student's academic standing is computed automatically in real time using the following hierarchical criteria:

1. **Needs Attention** *(Red)*:
   - **Condition:** Attendance $< 70\%$ **OR** Average Marks $< 40\%$
   - **Recommendation:** *"Student requires immediate support to improve attendance or academic performance."*
2. **Monitor** *(Yellow)*:
   - **Condition:** Attendance between $70\%$ and $74.9\%$ **OR** Average Marks between $40\%$ and $49.9\%$
   - **Recommendation:** *"Student needs regular monitoring and improvement."*
3. **On Track** *(Green)*:
   - **Condition:** Attendance $\ge 75\%$ **AND** Average Marks $\ge 50\%$
   - **Recommendation:** *"Student is performing well. Maintain consistency."*

### Attendance Color Legend
- **Green ($\ge 75\%$)**: University compliant & eligible for semester examinations.
- **Yellow ($70\% - 74\%$)**: Warning bracket; requires monitoring and faculty advisory.
- **Red ($< 70\%$)**: Critical attendance shortage; requires immediate intervention.

### 6 Chart.js Analytics Visualizations
Located on the **Branch Comparison** page:
1. **Bar Chart**: Total student enrollment across AI, AIDS, AIML, DS, and CYBER.
2. **Bar Chart**: Branch-wise average attendance percentage.
3. **Bar Chart**: Branch-wise average academic marks percentage.
4. **Doughnut Chart**: Institutional distribution of On Track, Monitor, and Needs Attention students.
5. **Scatter Chart**: Correlation between student attendance and average academic score.
6. **Horizontal Bar Chart**: Subject-wise average scores across the first-year curriculum.

## 3. Technologies Used

- **Backend**: Python 3.12, Flask Framework (Session-based authentication, routing, context processors, decorators)
- **Security**: Werkzeug (`generate_password_hash`, `check_password_hash`) for salted SHA-256 password security
- **Database**: SQLite3 (`database.db`) with foreign key constraints, cascading deletes, and multi-table relationships
- **Frontend**: Semantic HTML5, Custom Responsive CSS3 (Academic Blue `#0f2b48` & `#1d4ed8`, White, Slate Gray `#f8fafc`)
- **Data Visualizations**: Chart.js v4.4 (CDN)
- **Icons & Typography**: Font Awesome 6 (CDN), Modern System Sans-Serif Typography

## 6. Installation & How to Run

### Step 1: Clone or Navigate to Project Directory
```powershell
cd "c:\Users\HP\OneDrive\smart attendance project"
```

### Step 2: Install Dependencies
```powershell
pip install -r requirements.txt
```
*(Flask and Werkzeug are the only external dependencies required; SQLite comes built into standard Python).*

### Step 3: Initialize and Seed the Database
```powershell
python database.py
```
This initializes all 6 SQLite tables and seeds 20 realistic student records across all 5 branches, complete with attendance, marks, and calculated recommendations.

### Step 4: Run the Application
```powershell
python app.py
```
The application will launch locally at:
```
http://127.0.0.1:5000
```
Open this address in any modern web browser.

## 9. Future Scope

> **Official Future Scope:**  
> *“The current application uses rule-based analysis to identify students needing support. In the future, machine-learning models can be introduced to predict final academic performance using attendance, internal marks, assignment scores, and previous-semester performance data.”*

### Potential Technical Enhancements
1. **Predictive ML Pipelines**: Integrate scikit-learn models (Random Forest / Gradient Boosting) to forecast end-semester Grade Point Averages (GPA) at week 6 of the term.
2. **Automated Parent/Mentor SMS Alerts**: Trigger automated SMS/Email notifications via Twilio or SendGrid when attendance falls below 75%.
3. **Biometric & RFID Integration**: Ingest real-time attendance logs directly from campus turnstiles or classroom RFID scanners via RESTful APIs.
4. **Export Engine**: One-click generation of university-compliant PDF detention lists and Excel grade sheets.
